# Entries presentation restoration

The source reference is main commit `0e9f7a81`, specifically BlogCard/BlogHeader/BlogAuthor, PhotosTileContent/PhotosTitleCard/PhotosModeSwitch/WindowDisplay, ProjectsTileContent/ProjectsHeader, and their layout styles. The v11 data and native window/media contracts remain in use.

Blog listings use the original horizontal composition: compact author portrait and name, bold UI-font title, desktop description, date and parsed reading time, and the rounded side cover. The RSS/search tools retain their compact rounded placement. Projects use the original 8.5rem mobile / 12rem desktop square material tiles, project marks, and desktop hover labels. Album entries use image-led masonry at authored mobile/desktop column widths with intrinsic measured aspect ratios. The persisted gallery setting switches between entry covers and all measured images; individual images open the existing native lightbox. The implementation does not invent image dimensions or reaction counts.

The listing summary has an optional validated `display` projection containing project icon, album images and parsed reading minutes. Rebuilt indexes carry available icon/image metadata. Missing display fields in older indexes are enriched on the server using the already tagged complete entry/document reads, then cached with the section's hour lifetime. Browsers do not issue one detail fetch per card. Enriching an older index depends on valid published entry metadata; strict detail validation is retained, so a malformed indexed detail produces the normal section error instead of a fabricated display field. Index drift comparison now recursively includes nested image/icon metadata, so changed project marks and photograph geometry are detected during reindexing.

Reader titles and document headings use bold UI typography, with Pacifico reserved for its authored display uses elsewhere. Blog identity rows restore portraits and the two-line author/date structure. Project headers restore the project mark and material metadata/link row. Projects with measured media restore the original WindowDisplay image-left / independently scrolling article-right composition on desktop, with contained window sizing and a narrower stacked layout. A cover already present in the gallery is shown once; a distinct authored cover is retained as the first measured image. Album readers restore portrait/location/date/Instagram identity and an image/content split on desktop. The main carousel fills its image pane with the existing cover fit; switching to the native grid retains natural measured thumbnail geometry. Native carousel, grid, captions and lightbox behavior are retained. Reader share/download controls use the existing authored icons and preserve explicit accessible labels, canonical links and download actions. Table-of-contents placement is inline at ordinary widths and floating on wide full-page readers. Contained readers use a collapsed outline.

The client renderer used by windows and entry overlays suppresses full-page margins and large route padding. Window browsing reuses the per-section entry presentation in a compact contained surface instead of generic text buttons. Entry selection updates the current window instance; modified anchor clicks retain canonical page navigation. Browsing back to the list preserves the window identity. The paginated read API enriches only its selected page, after viewer/unlisted filtering, using the same cached display helper as route listings. Sparse fieldsets can request `display` explicitly. Native window chrome and overlay behavior remain independently owned. Shared surface rendering, notebook, comments and Settings presentation are separate restoration workstreams.
